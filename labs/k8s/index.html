TROUBLESHOOTING

Issues I Worked Through

The container exited because the application encountered an error. I investigated the application instead of assuming Docker itself was the problem.

I opened an interactive shell inside the container, inspected the application files, and identified that the helper filename did not match the import used by the Node.js application.

After correcting the application files, I learned that the Docker image had to be rebuilt before a new container would contain the updated source.

Another container was already bound to the host port. I identified the running container and resolved the conflict before starting the updated workload.

WHAT I LEARNED

Key Takeaways

  • A Dockerfile contains instructions used to build an image; it is not the image itself.
  • A container is a running instance of an image.
  • Source changes require rebuilding the image before a new container includes them.
  • Container failures can come from the application running inside the container, not only Docker.
  • Host ports must be available before Docker can publish a container port to them.
