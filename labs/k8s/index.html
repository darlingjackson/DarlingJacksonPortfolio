01 / OVERVIEW

A Kubernetes lab built around understanding.

The goal is not simply to get an application running. Each phase is designed to show what Kubernetes is doing, why the resource exists, how to inspect it, and how to troubleshoot it.

01
◈
UNDERSTAND

Learn the system before automating it.

The lab begins with cluster architecture, desired state, controllers, scheduling, workloads, networking, and Kubernetes behavior before introducing abstraction.

ENGINEERING METHOD

Understand before abstracting.

01 Understand

Learn what the Kubernetes resource solves and where it sits in the architecture.

02 Build

Implement the resource manually and inspect what Kubernetes creates.

03 Break

Intentionally create failures and diagnose them through logs, events, and state.

04 Automate

Introduce Helm and CI/CD only after the underlying workflow is understood.
