STANDARD OPERATING PROCEDURE

The rules that govern the authorization workflow.

RMF-SOP-001 Security Authorization Procedure
Controlled Lab Procedure
1. PURPOSE

Establish a repeatable process for coordinating RMF security authorization activities for the Foxhole Portal case study.

2. SCOPE

Applies to the fictional Foxhole Portal system, its authorization boundary, security documentation, implementation evidence, assessment results, authorization decisions, and continuous monitoring activities.

3. PROCESS RULE

Each phase must produce the information, decisions, and records required for the next phase. Open findings remain visible until they are resolved, accepted, transferred, or tracked.

4. RECORDKEEPING

System documentation is treated as a living authorization record and is updated as the system, controls, findings, and risk change.

OPERATING MODEL

Work moves through four repeatable actions.

01 RECEIVE

Use the current system record as the starting point.

02 EXECUTE

Perform the required security and RMF activities.

03 RECORD

Document decisions, evidence, findings, and risk.

04 HAND OFF

Provide the next phase with usable inputs.

03

ROLES + RESPONSIBILITIES

Authorization work has clear ownership.

01 System Owner

Owns the business need, system requirements, resources, and operational decisions.

02 ISSM / ISSO

Coordinates security status, documentation, evidence, findings, and authorization activities.

03 Security Engineering

Translates security requirements into technical design, configuration, and implementation evidence.

04 Control Assessor

Evaluates control implementation and documents assessment results and deficiencies.

05 Authorizing Official

Reviews the authorization package and makes the risk-based authorization decision.

RMF PROCEDURE

What happens in each phase.

PHASE PRIMARY ACTION EXPECTED HANDOFF OPEN
01 Prepare

Establish organizational and system context, stakeholders, scope, boundary, inventory, and initial risk.

Defined authorization context and system-level inputs for categorization.

↗
02 Categorize

Identify information types and determine the impact of loss of confidentiality, integrity, and availability.

Documented system security categorization and rationale.

↗
03 Select

Select and tailor controls based on categorization, operating environment, and risk.

Control baseline, tailoring decisions, and allocation.

↗
04 Implement

Apply selected controls and document how protections are implemented within the system.

Implementation statements and supporting evidence.

↗
05 Assess

Evaluate whether controls are implemented correctly and operating as intended.

Assessment results, findings, and remediation records.

↗
06 Authorize

Present the authorization package and residual risk for a risk-based decision.

Authorization decision, conditions, and accepted risk.

↗
07 Monitor

Maintain awareness of control status, system change, findings, vulnerabilities, and risk.

Updated security status for continued authorization.
